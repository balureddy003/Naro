# 2. PRD (Product Requirements Document)

## Goal

Turn research into a scoped, reviewable definition of what will be built, at what autonomy level, and with what risks accepted.

## Key artifact

**PRD** should contain:

- Problem and success metrics (from research)
- In-scope / out-of-scope
- User journeys or agent goals
- Autonomy level per goal or tool class (Advise / Act with Approval / Act Autonomously)
- Data sources and quality assumptions
- Non-functional requirements (latency, cost budget, audit retention)
- Risks and mitigations
- Open questions and owners

## Exit gate

Product, engineering, and risk owners sign off on scope, autonomy levels, and accepted risks.
